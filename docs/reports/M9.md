## 1. Executive Summary

The **Sustainable Enterprise Resource Planning (S-ERP) DBMS** is a complete, production-grade enterprise database application designed to fulfill the academic framework established by **Chofreh, Goni, & Klemeš (2018)** (*Journal of Cleaner Production* 198, pp. 1383–1392) in conjunction with the domain Entity-Relationship and Use Case specifications (`docs/source/er-usecase.png`).

The core distinguishing architectural feature of this system is its **interchangeable dual-engine persistence layer**:
- **SQL Engine:** Relational database backed by **MySQL 8.4 LTS** utilizing native InnoDB foreign keys, unique indexes, and domain `CHECK` constraints.
- **NoSQL Engine:** Document database backed by **MongoDB 6.0 LTS** bridged via low-level in-memory **AlaSQL** relational projections to guarantee identical ANSI SQL query execution without driver differences leaking into business logic.

Both engines operate **without heavyweight ORMs** (e.g. Prisma, TypeORM, Hibernate) by executing parameterized relational queries directly via low-level native drivers (`mysql2` and official `mongodb` client), adhering strictly to hardware constraints (512 MB memory caps per container).

## 3. Academic Framework Mapping (Chofreh et al., 2018)

The implementation maps 1:1 to the foundational paradigms of the research literature:

### 3.1 Sustainability Paradigm (Triple Bottom Line)
1. **Environmental Dimension (`dimension_id: 1`):** Quantified through Scope 1/2 greenhouse gas emissions (metric tons CO2e), electrical energy intensity (kWh/ton), and process water consumption (m3).
2. **Social Dimension (`dimension_id: 2`):** Quantified through occupational health and safety incident rates, employee training investment hours, and gender wage equity ratios.
3. **Economic Dimension (`dimension_id: 3`):** Quantified through clean technology return on investment (ROI %), eco-friendly material procurement percentages, and regulatory non-compliance penalties.
4. **Primary Focus Operationalization:** The organization strategically designates its primary dimension (`organization_dimension`), dynamically driving dashboard weighting and executive alerting.

### 3.2 Decisional Paradigm (Three-Tier Decision Framework)
1. **Strategic Tier:** Handled exclusively by `Strategic Manager` and `Administrator`. Defines long-term sustainability targets, environmental policies, and capital investments.
2. **Tactical Tier:** Managed by `Tactical Manager`. Coordinates cross-departmental projects, work breakdown tasks, resource allocations, and implementation roadmap phases.
3. **Operational Tier:** Handled by `Operational User`. Executes day-to-day shop-floor data collection, task progress reporting, and equipment meter readings.
4. **Decisional Integrity:** Enforced by route-level authorization guards. If a Tactical Manager attempts to log a Strategic policy decision, the application halts execution with HTTP 403 Forbidden.

### 4.1 Low-Level Driver Philosophy (Zero ORM)
Traditional ORMs obscure database operations, generate inefficient relational joins, and lack true portability between relational and document models. S-ERP DBMS utilizes:
1. **Direct Parameterized Queries:** Every query uses `?` placeholders with strictly separated parameter arrays, preventing SQL injection vulnerabilities.
2. **AlaSQL Bridge Execution:** On MongoDB, documents are loaded into memory and evaluated against standard ANSI SQL queries, providing identical aggregation, filtering, and foreign key emulation without duplicating business logic.

## 7. Clean Clone Reproduction & Verification Guide

To spin up and verify the complete application from a fresh clone:

```bash
# 1. Clone repository
git clone https://github.com/keerthivasan1717/S-ERP-DBMS.git
cd S-ERP-DBMS

# 2. Configure environment
cp .env.example .env

# 3. Start dual database engines in Docker
docker compose up -d

# 4. Install dependencies
npm install --ignore-scripts

# 5. Execute schema migrations on both engines
npm run migrate

# 6. Seed demo enterprise dataset
npm run seed -- --reset

# 7. Execute schema conformance check
npm run er-check

# 8. Run full test suite (typecheck + lint + 67 vitest tests)
npm run check

# 9. Build frontend and backend bundles
npm run build

# 10. Start production server
npm run dev:server
```

Open `http://localhost:3000` and sign in with any of the demo roles:
- `admin` / `1234`
- `strategic` / `1234`
- `tactical` / `1234`
- `operator` / `1234`
