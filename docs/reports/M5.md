## 1. Summary

Milestone M5 delivers the tactical project portfolio and resource planning system for the S-ERP DBMS application. Designed for the `Tactical Manager` role, this module coordinates cross-departmental sustainability projects, work breakdown tasks, implementation roadmap phases, project risks, and personnel resource allocations.

Key deliverables accomplished in this milestone:
1. **Tactical Project Portfolio & Lifecycle (`ProjectsPage.tsx`, `tactical.routes.ts`):** Complete CRUD management for Projects (`project`) with statuses (`Planned`, `Active`, `On Hold`, `Completed`), target start and completion dates, and owning department references.
2. **Integrated Project Detail View:** A composite tactical dashboard rendering all four related project facets in one integrated view:
   - **Work Breakdown Tasks (`project_task`):** Discrete operational milestones with statuses and execution schedules.
   - **Implementation Phases (`implementation_phase`):** Three-tier S-ERP roadmap stages (`Pre-implementation`, `Implementation`, `Post-implementation`).
   - **Team Allocation & Personnel (`employee_project`):** Personnel assignments with specific project roles and percent resource commitments.
   - **Project Risks (`risk`):** Risk registers tracking title, description, and severity ratings (`Low`, `Medium`, `High`).
3. **100% Total Employee Allocation Constraint:** Implemented and verified the cross-project workload ceiling: an employee's aggregate allocation percentage across all active projects cannot exceed 100%. Attempts to over-commit personnel are halted with HTTP 400 Bad Request.
4. **Automated Testing & Parity Evidence:** 61 automated test cases across 5 test suites validating project lifecycle CRUD, 100% allocation rejection, and composite detail retrieval on both MySQL 8.4 and MongoDB 6.0.

## 4. Database Detail

### 4.1 100% Employee Allocation Ceiling Logic

The workload ceiling ensures personnel are not over-allocated across multiple active projects:

```typescript
// Enforced in TacticalRepo.addMember
const alloc = data.allocation_percentage ?? 100.0;
const existing = await this.db.query<any>(
  'SELECT SUM(allocation_percentage) AS total_alloc FROM employee_project WHERE emp_id = ? AND project_id != ?',
  [data.emp_id, projectId]
);
const currentAlloc = Number(existing[0]?.total_alloc || 0);
if (currentAlloc + alloc > 100.0) {
  throw new Error(`Total allocation for employee cannot exceed 100% (current: ${currentAlloc}%, attempted +${alloc}%).`);
}
```

### 4.2 Engine Differences Handled

| Feature / Behavior | MySQL 8.4 | MongoDB 6.0 | Adapter Solution |
|---|---|---|---|
| **Composite Primary Key (`employee_project`)** | `PRIMARY KEY (project_id, emp_id)` | Unique compound index `{ project_id: 1, emp_id: 1 }` | `TacticalRepo` checks existing assignment and updates or inserts accordingly. |
| **Cascade Task Deletions** | `FOREIGN KEY (project_id) REFERENCES project(project_id) ON DELETE CASCADE` | Handled via collection delete query in adapter | Deleting a project removes associated child tasks, phases, and risk entries. |
| **Risk Severity Enumeration** | `CHECK (level IN ('Low', 'Medium', 'High'))` | Zod schema & application validation | Both engines reject invalid risk ratings outside the permitted domain. |

## 5. How It Works

### 5.1 Project Creation & Comprehensive Detail Breakdown
1. **Project Initiation:** Tactical Manager navigates to "Projects & Tasks" and creates a new project (e.g. *Closed-Loop Circular Water Recycling*).
2. **Deconstruction:** The manager selects the project to inspect its detail dashboard. Four sub-lists are populated via `GET /api/tactical/projects/:id`.
3. **Tasks & Phases:** Tasks are scheduled with milestone dates; implementation phases are aligned to the roadmap.
4. **Member Assignment & Allocation Ceiling:** Manager adds an employee with a specified percentage. If the cumulative percentage across all initiatives exceeds 100%, the request is halted with HTTP 400.
