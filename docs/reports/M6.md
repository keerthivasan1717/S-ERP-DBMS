## 1. Summary

Milestone M6 establishes the core sustainability metrics engine of the S-ERP DBMS application, bridging the academic framework defined by Chofreh, Goni, & Klemeš (2018) with concrete dual-database persistence. This milestone implements the triple bottom line paradigm (Environmental, Social, Economic) and its structural operationalization across departments and shop-floor operations.

Key deliverables accomplished in this milestone:
1. **Sustainability Dimensions & Indicators Matrix (`IndicatorsPage.tsx`, `sustainability.routes.ts`):** Hierarchical visualization grouping operational sustainability metrics under Environmental, Social, and Economic dimensions with unit classifications, target baselines, and dynamic latest recorded values.
2. **Measurement History & SVG Sparkline Trend Visualizer:** An indicator inspection drawer rendering historical time-series logs with an SVG vector sparkline visualizing quantitative metric trends over time.
3. **Operational Daily Logging & Future Date Prevention (`operational.routes.ts`, `OperationalPage.tsx`):** A dedicated interface for `Operational User` personnel to record time-stamped metric readings with automatic session-based attribution (`recorded_by`). Validation rejects future timestamps (`measurement_date > CURRENT_DATE`).
4. **Duplicate Measurement Date Constraint (Gap G4):** Direct rejection of duplicate readings for the same indicator on the same date across both SQL and NoSQL engines, maintaining data fidelity.
5. **Strict Role-Based Access Control (RBAC):** Verified that `Strategic Manager` holds authoring rights over indicator definitions, whereas `Operational User` is restricted strictly to measurement logging (HTTP 403 Forbidden on definition alterations).

## 4. Database Detail

### 4.1 Schema Entities & Relationships

- **`sustainability_dimension`**: Identifies the 3 pillars (`dimension_id`, `name`, `description`).
- **`organization_dimension`**: Maps the organization's strategic posture (`org_id`, `dimension_id`, `priority_level`).
- **`sustainability_indicator`**: Metric definitions (`indicator_id`, `dimension_id`, `name`, `code`, `unit`, `target_value`, `baseline_value`, `direction`).
- **`indicator_measurement`**: Quantitative observation logs (`measurement_id`, `indicator_id`, `value`, `measurement_date`, `source`, `recorded_by`, `created_at`).

### 4.2 DDL Excerpt (MySQL)

```sql
CREATE TABLE IF NOT EXISTS indicator_measurement (
  measurement_id INT AUTO_INCREMENT PRIMARY KEY,
  indicator_id INT NOT NULL,
  value DECIMAL(12, 4) NOT NULL,
  measurement_date DATE NOT NULL,
  source VARCHAR(255) NOT NULL,
  recorded_by INT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (indicator_id) REFERENCES sustainability_indicator(indicator_id) ON DELETE RESTRICT,
  FOREIGN KEY (recorded_by) REFERENCES employee(emp_id) ON DELETE RESTRICT,
  INDEX idx_measurement_indicator_date (indicator_id, measurement_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4.3 Engine Differences & AlaSQL Date Adaptation

In MySQL, `measurement_date` is stored as a native SQL `DATE` with index lookups. In MongoDB, date values are serialized as ISO-8601 strings (`YYYY-MM-DD`). Because AlaSQL's aggregate functions (`MAX`) operate numerically on JavaScript timestamps, the `MongoAdapter` normalizes date strings during table loading and translates query parameters dynamically, guaranteeing complete functional parity between both engines without driver differences leaking into application logic.

## 5. How It Works

1. **Strategic Metric Alignment:** Strategic managers review the dimensions ledger (`/indicators`), viewing operational indicators associated with Environmental, Social, and Economic goals.
2. **Shop-Floor Data Entry:** Operational operators in production or environmental facilities record daily readings via `/operational`. The backend checks that `measurement_date <= CURRENT_DATE` and ensures no prior reading exists for that date (Gap G4).
3. **Audit Trail & Attribution:** The system automatically extracts `emp_id` from the secure session cookie, stamping `recorded_by` without relying on client input.
4. **Trend Analysis:** Clicking any indicator presents historical readings alongside an SVG-drawn vector trend line showing directionality towards sustainability targets.

## 8. Deviations & Decisions

- **Gap G4 Duplicate Date Handling:** To resolve Gap G4 identified in the schema analysis, `OperationalRepo.enterMeasurement` checks for an existing record matching `(indicator_id, measurement_date)`. If found, it raises a 400 Bad Request error.
- **Sparkline Implementation:** Created a pure mathematical SVG path renderer directly in React without introducing heavy third-party graphing dependencies (e.g. Chart.js, Recharts), conforming strictly to resource constraints.

---

## 9. Known Issues and Limitations

- AlaSQL in-memory querying requires date normalization for `MAX()` aggregate calculations. This has been solved inside `MongoAdapter` without modifying business logic.
- Editing of past measurements is not currently permitted for operational users; historical entries are immutable audit records.
