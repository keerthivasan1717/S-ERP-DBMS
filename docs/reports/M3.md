## 1. Summary

Milestone M3 delivers the user-facing web interface and application shell for the S-ERP DBMS application. Built with React 19, TypeScript, and Vite, the UI adheres strictly to the deliberate anti-AI aesthetic defined in `plan.md` §7: handcrafted CSS variables, high data-density ledger tables, hairline 1px borders, 2px border radius, muted earthy colors (paper canvas `#F3F0E8`, warm surfaces `#FBFAF6`, ink text `#1E2421`, terracotta accent `#A9461F`), monospace tabular data figures, and absolute zero purple/blue gradients, glowing shadows, or filler marketing copy.

Key deliverables accomplished in this milestone:
1. **Dual-Engine Interactive Login Interface (`web/src/pages/LoginPage.tsx`):** Users select their target database engine (`SQL (MySQL 8.4)` on port 3307 or `NoSQL (MongoDB 6.0)` on port 27017) with real-time connectivity status badges polled live from `GET /api/engines/status`. Includes quick demo role buttons for all four S-ERP roles (`Administrator`, `Strategic Manager`, `Tactical Manager`, and `Operational User`).
2. **Persistent Application Shell & Header (`web/src/components/Header.tsx`, `App.tsx`):** A fixed application header displaying the project brand, active database engine badge (`SQL (MySQL 8.4)` vs `NoSQL (MongoDB 6.0)`), current username, user role, and a one-click session sign-out action.
3. **Role-Based Navigation Sidebar (`web/src/components/Sidebar.tsx`):** A responsive, hierarchical sidebar dynamically adapting its navigation trees according to the user's authenticated organizational role:
   - **Administrator:** Organization Profile, Department Tree, Employee Directory, User Accounts, and system-wide visibility.
   - **Strategic Manager:** Sustainability Dimensions, Indicators, Strategic Governance Decisions, and Reports.
   - **Tactical Manager:** Projects & Tasks, Business Processes, Resource Tracking, and Implementation Phases.
   - **Operational User:** Daily Indicator Measurement Entry, Assigned Work Breakdown Tasks, and Operational Processes.
4. **Shared Ledger UI Component Suite (`web/src/components/`):**
   - `DataTable`: Dense tabular ledger supporting client-side column sorting, instant full-text filtering search, and pagination.
   - `StatusTag`: Small, border-framed, non-pill semantic badges for entity statuses (`active`, `planned`, `completed`, `on-hold`) and risk levels (`low`, `medium`, `high`).
   - `ConfirmModal`: Minimalist modal dialog for deletion and confirmation actions.
   - `EmptyState`: Clean hairline-bordered ledger empty state notice.
5. **Real-World Live Screenshot Capture:** Puppeteer-automated capture of 7 live screens across all roles and engine states saved directly to `docs/screens/m3/`.

## 4. Database Detail

### 4.1 Engine Selection & Dynamic Binding

The frontend communicates with backend endpoints that bind dynamically to either MySQL or MongoDB based on the signed session cookie:

- **MySQL Mode:** Session bound to MySQL connection pool (TCP port 3307). Queries execute via native `mysql2` driver.
- **MongoDB Mode:** Session bound to MongoDB client (TCP port 27017). Queries execute via AlaSQL bridge over collection documents.
- **Zero Cross-Engine Leakage:** The engine specified during login is stored in the signed JWT cookie; the client never passes database connection strings or raw driver configurations.

### 4.2 Engine Differences Handled in UI

| UI Element / Workflow | SQL (MySQL 8.4) | NoSQL (MongoDB 6.0) | Frontend Handling |
|---|---|---|---|
| **Engine Status Indicator** | Host: `127.0.0.1:3307` | Host: `127.0.0.1:27017` | Queried simultaneously via `/api/engines/status`; live dot indicator (`● reachable` / `○ offline`) rendered per engine. |
| **Engine Header Badge** | Displays `SQL (MySQL 8.4)` | Displays `NoSQL (MongoDB 6.0)` | Extracted from `user.engine` claim in session token and prominently displayed in header. |
| **Primary Key Display** | Integer IDs (e.g. `1`, `2`) | Integer IDs maintained by adapter | Tabular rows display numeric IDs uniformly formatted in monospace font (`IBM Plex Mono`). |

## 5. How It Works

### 5.1 End-to-End User Experience Flow

1. **Initial Visit & Engine Inspection:**
   - The user opens `http://localhost:3000`.
   - The application checks `GET /api/auth/me`. If no active session cookie exists, the user is presented with `LoginPage`.
   - `LoginPage` immediately queries `GET /api/engines/status` to determine whether MySQL 8.4 and MongoDB 6.0 are reachable, rendering status indicators.
2. **Engine Selection & Authentication:**
   - The user selects the desired engine (`SQL (MySQL)` or `NoSQL (MongoDB)`).
   - The user can type credentials or click any demo role chip (`Administrator`, `Strategic Manager`, `Tactical Manager`, `Operational User`) to pre-fill credentials (`1234`).
   - On submission, `POST /api/auth/login` verifies credentials and issues the `httpOnly` signed cookie.
3. **App Shell Initialization:**
   - On successful login, the app shell renders with the top header displaying the active engine badge, username, and role.
   - The sidebar mounts with role-filtered navigation items corresponding to the user's permission level.
4. **Ledger Navigation & Data Filtering:**
   - The user selects a navigation item (e.g. "Departments" or "Indicators").
   - Data is displayed in a dense, hairline-bordered `DataTable`.
   - The user can sort columns by clicking headers, search across all records using the integrated filter input, or browse pages with pagination controls.
5. **Sign Out:**
   - Clicking "Sign out" calls `POST /api/auth/logout`, clears the session cookie, and returns the user to the login screen.

## 9. Known Issues and Limitations

1. **Client-Side Filter Scope:** The `DataTable` instant search filter currently evaluates rows loaded in memory. For paginated API queries spanning thousands of rows, server-side search parameters will be added in subsequent milestones.
2. **Single-Page Navigation State:** Navigation between views is currently managed via React component state rather than browser URL pushState, ensuring lightweight execution without heavy routing dependencies.

From a clean clone:

