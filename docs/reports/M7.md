## 1. Summary

Milestone M7 delivers the operational governance and decisional paradigm foundations of the S-ERP DBMS application, reflecting the core hierarchy described by Chofreh, Goni, & Klemeš (2018): Strategic, Tactical, and Operational tiers. This milestone establishes enterprise resource tracking, business process sustainability linkages, multi-tiered decision logging with risk mitigation associations, and implementation-phase report archival.

Key deliverables accomplished in this milestone:
1. **Resource Inventory Management (`ResourcesPage.tsx`, `tactical.routes.ts`):** Complete cataloging and lifecycle management of physical, financial, and operational assets categorized across Energy, Material, Water, and Financial resource types with native unit tracking.
2. **Business Process Workflows & Sustainability Linkage (`ProcessesPage.tsx`):** Departmental operational processes (`business_process`) linked dynamically to physical resources (`process_resource` with quantity commitments) and sustainability indicators (`process_indicator`), operationalizing shop-floor sustainability.
3. **Decisional Paradigm & Level Enforcement (`DecisionsPage.tsx`, `decisions.routes.ts`):** Governance decision log enforcing the three decisional tiers (`Strategic`, `Tactical`, `Operational`). Server-side RBAC restricts Tactical Managers from recording Strategic policies (HTTP 403 Forbidden).
4. **Decision ↔ Risk Linkage (Gap G3 Resolved):** Many-to-many association connecting governance decisions directly to project risk registers (`decision_risk`), ensuring every mitigation decision references its identified risk factors.
5. **Phase Report Archival (Gap G5 Resolved):** Implementation roadmap phase reporting linking generated ESG and performance reports to specific project implementation milestones (`phase_report`), accessible across both database engines.
6. **Automated Verification:** 67 automated test cases passing on both MySQL 8.4 and MongoDB 6.0, verifying resource allocation, decision tier barriers, risk linkages, and report archival.

## 4. Database Detail

### 4.1 Schema Entities & Bridge Tables

- **`resource`**: Physical/financial resources (`resource_id`, `type`, `name`, `description`, `unit`).
- **`business_process`**: Operational processes (`process_id`, `name`, `description`, `department_id`).
- **`process_resource` (Bridge)**: Process resource allocation (`process_id`, `resource_id`, `quantity`, `unit`).
- **`process_indicator` (Bridge)**: Sustainability linkage (`process_id`, `indicator_id`).
- **`decision`**: Governance decisions (`decision_id`, `title`, `description`, `decision_level`, `date`, `created_by`, `project_id`, `process_id`).
- **`decision_risk` (Bridge G3)**: Mitigative risk links (`decision_id`, `risk_id`).
- **`report`**: Archived management reports (`report_id`, `title`, `type`, `generated_by`, `created_at`, `file_path`).
- **`phase_report` (Bridge G5)**: Roadmap phase association (`phase_id`, `report_id`).

### 4.2 DDL Excerpt (MySQL)

```sql
CREATE TABLE resource (
  resource_id INT AUTO_INCREMENT PRIMARY KEY,
  type VARCHAR(50) NOT NULL,
  name VARCHAR(255) NOT NULL,
  description TEXT NULL,
  unit VARCHAR(50) NOT NULL,
  CONSTRAINT chk_res_type CHECK (type IN ('Energy', 'Water', 'Material', 'Financial'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE process_resource (
  process_id INT NOT NULL,
  resource_id INT NOT NULL,
  quantity DECIMAL(12,2) NOT NULL,
  unit VARCHAR(50) NOT NULL,
  PRIMARY KEY (process_id, resource_id),
  CONSTRAINT fk_pr_proc FOREIGN KEY (process_id) REFERENCES business_process(process_id) ON DELETE CASCADE,
  CONSTRAINT fk_pr_res FOREIGN KEY (resource_id) REFERENCES resource(resource_id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE decision (
  decision_id INT AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  description TEXT NULL,
  decision_level VARCHAR(50) NOT NULL,
  date DATE NOT NULL,
  created_by INT NOT NULL,
  project_id INT NULL,
  process_id INT NULL,
  CONSTRAINT fk_dec_emp FOREIGN KEY (created_by) REFERENCES employee(emp_id) ON DELETE RESTRICT,
  CONSTRAINT fk_dec_proj FOREIGN KEY (project_id) REFERENCES project(project_id) ON DELETE SET NULL,
  CONSTRAINT fk_dec_proc FOREIGN KEY (process_id) REFERENCES business_process(process_id) ON DELETE SET NULL,
  CONSTRAINT chk_dec_level CHECK (decision_level IN ('Strategic', 'Tactical', 'Operational'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 5. How It Works

1. **Resource Allocation:** Tactical managers inventory enterprise resources (e.g. green power feeds, raw recycled feedstocks) and link them to operational business processes with target consumption quantities.
2. **Decisional Paradigm Execution:** 
   - A `Strategic Manager` logs corporate ESG policies (e.g. decarbonization roadmap).
   - A `Tactical Manager` logs project-level operational trade-offs (e.g. vendor selection).
   - If a Tactical Manager attempts to log a Strategic decision, the server rejects it with HTTP 403 Forbidden.
3. **Risk Association (G3):** Decisions can be tagged with one or multiple identified project risks, creating an immutable audit trail of which risks triggered specific executive decisions.
4. **Phase Report Archival (G5):** As implementation roadmap phases conclude, managers archive milestone reports linking directly to `implementation_phase`, preserving phase documentation.

## 8. Deviations & Decisions

- **Bridge Entity Implementation:** Gaps G3 (`decision_risk`) and G5 (`phase_report`) are implemented using explicit join tables in MySQL and collection-based relational arrays in MongoDB, maintaining standard relational integrity across both engines.
- **Role Tiering:** `Strategic Manager` and `Tactical Manager` permissions are enforced strictly in Express route middleware, guaranteeing that UI controls reflect underlying security guarantees.

---

## 9. Known Issues and Limitations

- Cascading deallocations for process resources are handled via foreign keys with `ON DELETE RESTRICT` for resource items to prevent accidental orphaned allocations.
- Direct file uploads for reports reference local server paths; cloud object storage integration is omitted in conformance with zero-external-dependency constraints.
